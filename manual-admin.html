運営メンバー（代表のみ）

登録コード ― パートナーを待たせない仕組み

新規登録した方は全員、最初は経営者（顧客）として始まります。パートナーには登録コードをお渡しください。初回ログインの「はじめの設定」で「認定パートナー」を選び、そのコードを入力するとその場でパートナーポータルが開きます。運営での権限変更は不要です。

  1. コードを発行する「運営メンバー」→ 🎫 登録コード → コード名・役割・使用上限を入れて「発行」。説明会ごと・月ごとに分けると使用状況が追えます。
  2. パートナーにお渡しする「コピー」ボタンでコードをコピーし、招待メールや説明会資料に記載します。
  3. 使い終わったら停止する「停止」を押すと以降は使えなくなります。使用回数・残り回数は一覧で確認できます。
コードは第三者に渡らないよう管理してください。コードを知っている人は誰でもパートナーとして登録できます。使用上限を必要な人数に絞り、配布が終わったら停止するのが安全です。運営（admin）権限はコードでは付与できません——運営アカウントは従来どおり「アカウントと役割の管理」からのみ設定します。
運営メンバー（代表のみ）

誰に、どこまで開けるか

運営コンソールは全部入りではありません。役員・委託契約者ごとに、見えるメニューを1つずつ設定できます。

  1. 「運営メンバー」→ アカウントと役割の管理で、対象の方の役割を運営にする
  2. 同じ行の「権限を設定」を押す運営（admin）の行にだけ表示されます。
  3. プリセット（COO／CFO／CTO／すべて選択）を当ててから、1つずつ調整するプリセットと差が出た時点で「個別設定」に切り替わります。一覧には「個別設定（7/13）」のように現在の状態が出ます。

開けるときは表示を確認

資金調達・全社売上・一斉配信・顧客編集の4項目には、何が見えるようになるかが注記されます。

「運営メンバー」だけは付与できません

すべて選択を押しても、この項目はグレーのままです。権限を配る権限を渡すと、その人が自分や他人の権限を自由に変えられてしまうためです。

メニューを隠すだけでは「見せない」ことになりません。Supabase側のRLS（Phase71／72）を適用して初めて、データそのものが読めなくなります。UIだけの制限は、開発者ツールから回避できます。

一覧・稼働モニタ

ランク（fde_rank）の設定はここで行います。ランクは外注費率に直結するため、未設定のままにしないでください。

2名体制（サブ担当）の申請 運営メンバー

承認画面は「運営メンバー」メニューにあります（代表のみ）。

メイン担当が申請した体制が届きます。報酬配分はメイン担当が決めています。承認するとサブ担当がその顧客を閲覧でき、配分が報酬計算に反映されます。

サブ担当がまだTsuguAiに登録していない場合は「本人のログイン後に有効化されます」と表示されます。その状態でも承認して構いません。本人が初回ログインした時点で自動的に紐づきます。
承認の判断材料：申し送りに引き継ぎの意図が書かれているか、配分が極端でないか（例：サブ90%）。実態と合わない配分は、後で報酬トラブルになります。

補助金マスタ

運営が制度を登録し、カルテに候補が出ます

ここに登録した制度が、パートナーの顧客カルテ「補助金ナビ」で顧客の業種・年商・資金使途に照らして自動表示されます。この画面を扱えるのは代表・COO・CTOです。

登録する項目

制度名・実施機関・上限額・補助率・締切・年商上限・従業員上限・対象地域・対象業種・資金使途・要件・公募要領URL。

締切が過ぎた制度と「停止」にした制度は候補に出ません。公募回の改定のたびに更新してください。

AIに判定させない理由

補助金は要件を1つ外すと不採択になります。AI任せで「該当します」と言い切るのは危険なため、運営が登録した制度だけを候補にし、地域要件・従業員数・加点項目は「要確認」として表示する設計です。

パートナーの役割は制度のご案内（情報提供）までと規程・研修で定めています。申請支援の依頼が来たら、専門家ネットワーク（行政書士等）への紹介対応になります。
経営計画

資金調達の記録と、成長ロードマップ連動

調達（融資・出資）を実行したら、必ずここに記録してください。ダッシュボードの成長ロードマップが自動で拾います。

  1. 「KPI・経営計画」→ 経営計画の資金調達リストに項目を追加
  2. 金額は百万円単位で入力1,000万円なら「10」、5,000万円なら「50」。桁を間違えるとロードマップの判定が狂います。
  3. 状況を「実行中」または「完了」にするこの状態のものだけが調達実績として集計されます（「申請中」「審査中」は計画扱い）。
成長ロードマップのステージ3「シード調達」は累計5,000万円で達成判定です。ステージ2「初期トラクション」はパートナー10名・顧問先10社・MRR50万円が目安になっています。
DD（デューデリジェンス）で参照される箇所でもあるため、実行のたびに記録しておくと後から遡らずに済みます。
データ基盤

試算表17項目と、そこから出る指標

売上・営業利益の2項目では財務力が分かりません。試算表に載る17項目（PL7・BS10）を保持し、そこから14指標を自動算出します。単位はすべて万円です。

財務力

自己資本比率／流動比率／有利子負債月商倍率／債務償還年数／インタレストカバレッジ

金融機関が見る水準で3段階に色分けしています。

支払サイト

売上債権・棚卸資産・買入債務の各回転日数とCCC

現金が何日拘束されているかが分かります。

収益性・企業価値

粗利率／営業利益率／EBITDA年換算／ネット有利子負債／企業価値の目安（EBITDA×3−純有利子負債）

入力元は3つ。試算表の取り込み（CSV・Excel・PDF・画像／様式を問わず読み取り、円・千円は万円に自動換算）、顧問税理士の入力、パートナーの手入力。どこから入っても同じ項目に入ります。
読み取れない様式の報告が来たら、科目名の照合パターンを追加すれば次から通ります。運用しながら精度が上がる作りなので、現場からの報告を集めてください。確実なのは会計ソフトのPDF出力です。

誰に、いつ、何が届くか

agent-heartbeat が毎朝6時（JST）に走ります。相手によって頻度が違います。

パートナー毎朝「今日の一手」。担当顧客全社のシグナルから3件まで。ほかに面談準備ブリーフ、新人指南、承継レーダー（月）、M&Aマッチング（水）、ナレッジ便り（金）。
経営者毎週月曜の朝「今週のひとこと」。今週の予定・新しい月次レポート・期日超過の課題・未返信のメッセージ・手元資金の記録から。
面談の前日にもお知らせが出ます（曜日を問いません）。
運営月次レポートの自動生成の結果メール（monthly-report／毎月1日）。
経営者向けは、もとは毎朝でした。社長は毎朝アプリを開く方ではなく、毎朝届く通知は3週間ほどで無視されるようになります。無視された通知は二度と読まれないため、週に一度に改めました。
ただし初めての方には曜日を待たせません。登録した週にいちども便りが来ないのは、いちばん期待されている時期に沈黙することになるためです。
お伝えすることが無い週は送りません。中身の無い便りを送ると、次から開かれなくなります。
運営にも見えないもの

継ナビくんへの相談は、運営も読めません

経営者と継ナビくんの会話は ai_messages に保存されますが、権限（RLS）で本人以外は読めません。運営も例外ではありません。

なぜそうしたか

全部が見えると分かった瞬間、経営者は継ナビくんに本音を書かなくなります。夜中に弱音を吐ける場所であることが、この機能の価値そのものです。

伝わるのは押されたぶんだけ

顧客が「担当パートナーに伝える」を押すと ai_shares に写しが作られ、担当・副担当・運営が読めます。参照ではなく写しなので、あとで顧客が履歴を消しても残ります。

受け取った側は書き換えられない

問いと答えは社長の言葉です。担当が触れるのは「読んだ印」だけで、それ以外はデータベース側の引き金で止めています。

社長からの手元資金（cash_checkins）

入れるのは本人だけ経営者がダッシュボードから、いまの預金残高（万円）を1日1行。任意です。
担当・運営は読むだけ書き換えられません。書き換えられたら、それは社長の申告ではなくなります。
薄いときは手当てが出る顧客の画面に、支払予定からの見通しと押せる先が3つ出ます。「担当パートナーに知らせる」を押すと、残高入りのメッセージが担当に届きます。
問い合わせを受けたときの答え方。「継ナビくんに相談した内容を運営で確認してほしい」と言われても読めません。顧客ご本人に、その回答の下の「✉️ 担当パートナーに伝える」を押していただくようご案内してください。

課金・契約 ①概要

報酬は「税抜」に率を掛けます

入金額には消費税が乗っています。そのまま外注費率を掛けると、お預かりしている消費税まで配分してしまいます。先に消費税を外してから率を掛けます。

入金（税込） 55,000　→　税抜 50,000　→　× 外注費率 60%　=　30,000円
税抜への直しは1円未満を切り捨てます（×10÷11。÷1.1 だと1円足りなくなります）。

源泉徴収は「個人へのお支払い」だけ

個人（個人事業主）100万円までの部分10.21%
同上100万円を超える部分20.42%
法人源泉徴収は生じません—
未設定差し引きません（分からないまま引くと、返す手間をお相手に負わせるため）—
個人か法人かは、ご本人に登録していただきます。パートナーの設定画面に「個人・法人の区別」があります。法人パートナー（エンタープライズ）は ep_orgs 側で持ちます。未登録の方には、設定をご案内してください。

運用

月次の締め ― 実行順序

  1. 月次の数字とレポートの状況を確認する数字は顧問税理士の入力・試算表の取り込み・パートナーの手入力のいずれか。承認は各パートナーが顧客カルテの「月次レポート」で行い、そこに「ひとこと」とPDF出力もあります。
  2. 入金をすべて記録するStripeは自動。M&A成約・保険・終活などStripe外の入金を手動記録。対象顧客を必ず選ぶ。
  3. パートナーのランクを確認・更新する「パートナー」欄。昇格があれば先に反映しないと、報酬計算が旧ランクのままになります。
  4. 2名体制の申請を処理する未承認のまま月をまたぐと、サブへの配分が発生しません。
  5. 報酬配分を計算する「課金・契約」→ 入金タブ → 年月を選択 →「パートナー報酬の配分」。3つの警告をすべて解消する。
  6. 確定額を帳簿に転記して支払うインボイス登録番号は各パートナーが設定画面で登録しています（支払通知書に記載）。
  7. 売上目標・実績を確認する⑥タブで年間目標に対する進捗を確認。

サポート管理

パートナーからの問い合わせの受信箱と、運営サポートAIのナレッジ管理。解約のご依頼もここに届きます。

サポート管理は左メニューにはありません。画面右下の継ナビくん → 「サポート」タブ → 「📥 受信箱を開く」で開きます。
解約のご依頼が届いたら。経営者ダッシュボードの「お支払い」から出された解約のご依頼は、この画面の上部に並びます。届くと右下の継ナビくんに赤い「⚠ 解約のご依頼 N件」が出ます。あわせて毎朝メールでもお知らせします（受付中のご依頼があるあいだ毎日届き、対応済みにすると止まります）。コンソールを開かない日でも見落としません。担当パートナーにも見えます（読むだけ。対応するのは運営です）。
①ご依頼の中身と担当パートナーを確認 → ②顧問契約の締め（最終月の請求・成果物のお渡し）→ ③「アカウントを削除する…」→ ④会社名を打ち込んで「削除する」。
③④でアカウントを消すと、試算表・相談・手元資金など紐づくものも一緒に消えます。戻せません。必要な資料は消す前にお渡ししてください。同じメールアドレスで登録し直した場合は新規のお客様として扱われ、以前の記録は引き継がれません。
削除は押し間違いでは通りません。ボタンを押しただけでは何も起きず、その方の会社名をそのとおりに打ち込むまで「削除する」は押せません。同じ確認はサーバー側でも行っています。削除できるのは経営者（顧客）のアカウントだけで、パートナー・運営・ご自身は、この画面からは削除できません（Supabase の Authentication → Users から行ってください）。
削除すると、その下の「削除したアカウント」に控えが残ります。いつ・どなたを・誰が消したか、担当パートナーは誰だったかを、あとから辿れるのはこの控えだけです。残っていた招待も自動で片づけられます（片づけないと、登録し直したときに以前の担当が再び付いてしまいます）。
サポートAIのナレッジは必ず登録してください。運営ルール・報酬規程・申請手順を登録しておくと、AIがその内容に基づいて回答します。未登録の場合、AIは運営固有の事項を推測で答えず、問い合わせを案内します（誤情報を防ぐための仕様です）。「有効」のものだけが読み込まれます。

運営として押さえておくこと

ランクの未設定を放置しない

報酬計算が0円になり、毎月手作業が発生します。パートナー登録時に必ず設定を。

手動記録の顧客ひも付けを省略しない

配分から漏れます。後から直すより、記録時に選ぶ方が確実です。

専門家名簿の料金は必ず最新に

顧客に開示される情報です。実際と違うと、パートナーの信用が傷つきます。

紹介依頼を溜めない

パートナーは顧客に「聞いてみます」と言った状態で待っています。

権限を渡したらRLSも適用する

メニューを隠すだけでは防げません。Phase71／72のSQLまで実行して初めて、データが読めなくなります。

退職・契約終了時は権限を落とす

「運営メンバー」で役割を戻すか、権限をすべて解除してください。アカウントを残したままにしない。

規程の改定予定：「認定パートナー 禁止行為ガイドライン」のうち、有資格のパートナー本人が実行してよいかという論点は現在改定を検討中です。弁護士レビューが完了するまでは現行の定めが適用され、画面上もそれに合わせた表現になっています。レビュー完了後、システム側の表示を一括で切り替えます。
