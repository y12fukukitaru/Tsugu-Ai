# 公開前の通し確認（9/12に向けて）

画面を開いて「赤が出ていないか目で探す」やり方は見落とします。
機械に拾わせて、人は**画面を開いて回るだけ**にします。所要 20〜30分。

---

## 手順1　表と列の確認（5分・画面を開かずに済む）

`supabase/migrations/CHECK_columns.sql` を SQL Editor に貼って **Run**。

アプリが読んでいる **303件の表・列の参照**を、実際のスキーマと突き合わせます。
先日の `onboarding_reports.id`（存在しない列を読んでいた）と同じ種類の不具合を、
画面を開かずに全部洗い出せます。

| 結果 | 意味 |
| --- | --- |
| `Success. No rows returned` | ✅ この種類の不具合はありません |
| 行が返る | ❌ その表・列が無い。**結果をそのまま報告してください** |

> RLS（権限）はこのSQLでは見ていません。それは手順2で確かめます。

---

## 手順2　画面を開いて回る（15〜20分）

### 2-1　記録を始める

ログインしたら **`Ctrl`+`Shift`+`J`** で Console を開き、下を貼って Enter。
（貼り付けを止められたら `allow pasting` と打ってから貼り直す）

```js
window.__ERRS=[];
(function(){const f=window.fetch;window.fetch=async function(){
  const r=await f.apply(this,arguments);
  if(!r.ok){let b='';try{b=await r.clone().text();}catch(e){}
    window.__ERRS.push({状態:r.status,url:String(arguments[0]).slice(0,150),中身:b.slice(0,220)});}
  return r;};})();
console.log('記録を開始しました。画面をひと通り開いてください。');
```

これで、失敗した通信が**エラーの中身ごと**記録されます。赤い文字を目で探す必要はありません。

> ⚠️ **ページを再読み込みすると記録は消えます。** 役割を切り替えるときは、
> 先に 2-3 で結果を取り出してから切り替えてください。

### 2-2　開いて回る

**左のメニューを上から順に全部**開きます。加えて、右下の継ナビくんも開いて全タブを見ます。

| 役割 | 開くもの |
| --- | --- |
| **顧客** | 左メニュー全部（ダッシュボード／月次レポート／経営課題／お支払い／財務・資金繰り／企業価値・試算結果／AI自動化診断／M&A活用／Tsugu投資・融資・M&A）＋ 継ナビくん6タブ（相談・**予定は月/週/一覧すべて**・メッセージ・お知らせ・連携・サポート） |
| **パートナー** | 左メニュー全部 ＋ **顧客カルテを1件開く**（中のタブも切り替える）＋ 継ナビくん7タブ |
| **運営** | 左メニュー全部（KPI・経営計画、課金・契約、監査ログ、運営メンバー、専門家ネットワーク、補助金マスタ を含む）＋ 継ナビくん |

**表示モードの切り替え（運営のプレビュー）では代用できません。** 実際にその役割の
アカウントでログインしてください。権限（RLS）はログインしている本人で判定されるため、
プレビューでは本物の顧客・パートナーが遭遇するエラーが再現しません。

あわせて、動くかどうかも見ておきます。

- [ ] 継ナビくんに1つ質問して、答えが返る
- [ ] 予定タブで「＋ 予定」から1件登録できる
- [ ] 継ナビくんに「明日10時に◯◯」と頼み、確認カードが出る
- [ ] メッセージを1通送れる（顧客⇄パートナー）

### 2-3　結果を取り出す

ひと通り開いたら、Console に貼って Enter。

```js
console.log('失敗した通信 '+window.__ERRS.length+'件');
console.table(window.__ERRS);
copy(JSON.stringify(window.__ERRS,null,1));
```

`copy(...)` でクリップボードに入ります。**そのまま貼って報告してください。**
`0件` なら、その役割は問題なしです。

---

## 手順3　報告する内容

1. 手順1のSQLの結果（`No rows returned` か、返った行）
2. 役割ごとの `__ERRS`（3回分）
3. 2-2 のチェック項目で動かなかったもの

これだけあれば、原因の特定と修正はこちらで行えます。

---

## 補足：なぜこの手順なのか

開発側の環境からは、本番の Supabase にも公開中のサイトにも接続できません。
そのため**実データでの確認は、必ず人の手が要ります**。
その代わり、人がやることを「画面を開く」だけに減らし、
判断（何が壊れているか）は機械とこちら側で引き受ける形にしています。
