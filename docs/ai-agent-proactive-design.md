# TsuguAi -継- プロアクティブAIエージェント設計書

**結論：できます。しかも、いまの構成（GitHub Pages + Supabase + ai-proxy）のまま、追加インフラなしで始められます。**

この文書は「AIが待つ側から、働きかける側に回る」ための設計書です。
合わせて、このリポジトリにすぐデプロイできる雛形を追加しています。

- `supabase/migrations/20260807000000_agent_insights.sql` — AIからの提案を貯めるテーブルと定期実行の設定
- `supabase/functions/agent-heartbeat/index.ts` — 毎朝、全パートナーの顧客データを巡回して「今日の一手」を生成するEdge Function

---

## 1. 現状の整理

いまのTsuguAiのAIは **「呼ばれたら答える」** 構造です。

```
パートナーがボタンを押す → sb.functions.invoke('ai-proxy') → Claude → 回答表示
```

AI秘書・AI診断・各種提案生成、すべてこの形です。一方で、通知センター（🔔）は
**クライアント側でその場で計算するルールベース**（buildTodos）であり、AIは関与していません。

つまり「AIの頭脳」と「働きかける仕組み（通知）」が既に両方あるのに、**繋がっていない**。
プロアクティブ化とは、この2つを **サーバー側で定期的に繋ぐ** ことです。

## 2. プロアクティブ化の中核アーキテクチャ

```
[pg_cron（Supabase内の定期実行）]
        │ 毎朝 6:00 JST
        ▼
[Edge Function: agent-heartbeat]
        │ ① パートナーごとに担当顧客のデータを横断スキャン（ルールベースで「シグナル」抽出）
        │ ② シグナルをClaudeに渡し「今日の一手」ブリーフを生成
        ▼
[agent_insights テーブルに保存]
        │
        ├─ Phase 1: アプリ内 …… 通知センター🔔・AI秘書の冒頭に「AIからの提案」として表示
        ├─ Phase 2: メール …… 朝のブリーフをメール配信（Resend等）
        ├─ Phase 3: LINE …… LINE公式アカウントからプッシュ（日本の経営者に最も届くチャネル）
        └─ Phase 4: Google連携 …… Calendar/Gmail/Sheetsと双方向連携
```

ポイントは **「シグナル抽出はルール、文章化と優先順位付けはAI」** という分業です。
全データを毎回AIに読ませるのではなく、SQLで確実に拾える事実（期日・沈黙・未提出）を
ルールで抽出し、AIには「どれが今日いちばん大事か」「どう声をかけるか」を任せます。
これによりコストは1パートナーあたり1日1円未満に収まり、誤検知も起きにくくなります。

### シグナルの例（既存テーブルだけで検出できるもの）

| シグナル | 検出元 | AIが生成する働きかけ |
|---|---|---|
| 3日以内に面談予定 | meetings_scheduled | 面談準備ブリーフ（後述の目玉機能） |
| 課題の期日超過・2週間更新なし | pdca_items | 「◯◯社の課題が止まっています。一言連絡を」 |
| 月次レポート未作成・未承認 | monthly_reports | レポートのドラフトを先回り生成して提示 |
| 試算表が2ヶ月未入力 | financial_entries | 「数字が途切れています＝解約の前兆。フォローを」 |
| 顧客とのやり取りが30日以上ない | chat_messages | フォロー文面の下書き付きでアラート |
| 締切が近い補助金×該当しそうな顧客 | subsidies × profiles | 「この補助金、◯◯社が使えます。締切◯日」 |
| 資金繰り悪化の傾向 | cashflow_snapshots | 「◯◯社の現預金が3ヶ月連続減。面談を前倒しては」 |

**沈黙検知は特に重要です。** 直近のコミットで「返金・解約の芽を摘む」対応を入れていますが、
解約の芽は「顧客が何も言ってこなくなること」に最初に現れます。人間は静かな顧客を忘れますが、
AIは忘れません。これはプロアクティブAIでしか実現できない解約防止策です。

## 3. フェーズ計画

### Phase 1（2〜3週間）：アプリ内プロアクティブ — 外部依存ゼロ

1. `agent_insights` テーブル作成（同梱のSQL）
2. `agent-heartbeat` デプロイ + pg_cron設定（同梱の雛形）
3. フロント側：ログイン時に `agent_insights` を読み、
   - 通知センター🔔の最上部に「AIからの提案」枠を追加
   - AI秘書を開いたとき、冒頭に今朝のブリーフを表示。「詳しく」と打てばそのまま会話に接続
     （AI秘書の会話は既にlocalStorage永続化されているので、ブリーフを最初のassistantメッセージとして差し込むだけで自然につながります）

**この時点で「AIから働きかけてくれる」体験は完成します。** 課金も外部審査も不要。

### Phase 2（+1週間）：メール配信

毎朝のブリーフをメールでも届けます。Supabase Edge FunctionからResend（月3,000通まで無料）を
呼ぶだけ。アプリを開かない日でもAIが接点を持ち続けます。

### Phase 3（+2〜3週間）：LINE連携 ← Googleより先を推奨

日本の中小企業経営者・士業に確実に届くプッシュチャネルはメールでもアプリでもなくLINEです。
LINE Messaging APIは審査が軽く（Googleの機密スコープ審査より遥かに速い）、
公式アカウントは無料枠（月200通〜）から始められます。
「TsuguAi公式LINEを友だち追加 → パートナーIDを紐付け → 毎朝ブリーフが届く、返信すればAI秘書がそのまま応答」
という体験は、このセグメントでは事実上の独自機能になります。

### Phase 4：Google連携（ご質問への回答）

**できます。** ただし優先順位と審査コストを踏まえた順番があります。

#### 4-1. Google Calendar（最初にやるべき・審査が軽い）

- Supabase AuthはGoogleログインを標準サポートしており、スコープに `calendar.events` を追加して
  `provider_token` / `provider_refresh_token` を保存すれば、Edge FunctionからCalendar APIを呼べます
- **使い方1（読み）**: パートナーのカレンダーから顧客との面談を検出 → 前日に面談準備ブリーフを自動生成
  （既存の `meetings_scheduled` と突合し、TsuguAiに未登録の面談も拾える）
- **使い方2（書き）**: TsuguAiで面談を登録したらGoogleカレンダーにも自動作成、リマインダー付き
- Calendarスコープは「機密（sensitive）」扱いですが、Gmailの「制限付き（restricted）」より審査は軽く、
  数週間で通ります

#### 4-2. Gmail（2番目・審査重い）

- フォローメール・面談お礼・資料依頼の **下書きをAIが作ってGmailの下書きフォルダに置く**
  （勝手に送らない。送信ボタンを押すのは人間 — これが信頼設計の要）
- 注意: Gmailスコープは「restricted」扱いで、Google審査 + 場合によってはCASA（セキュリティ評価）が必要。
  年1回の再審査もあります。**先にCalendarで価値を証明してから着手**が正解です

#### 4-3. Google Drive / Sheets（データ取り込み）

- 顧客の試算表・決算書スプレッドシートをDriveから読み、`financial_entries` の下書きを自動生成
  → パートナーは「確認して保存」だけ。月次の入力作業がほぼ消えます
- 会計ソフト（freee/マネーフォワード）のAPI連携まで行くと強力ですが、まずはSheets読み取りが現実的

#### 実装の骨子

```
1. Supabase Dashboard → Auth → Google provider に追加スコープを設定
2. ログイン時に provider_refresh_token を google_tokens テーブル（RLS: 本人のみ）に保存
3. agent-heartbeat がトークンをリフレッシュして Calendar API を呼ぶ
4. 取得した予定を meetings_scheduled と突合 → ブリーフ生成
```

## 4. 「唯一無二」にする差別化案

Google連携そのものは他社にもあります。TsuguAiにしかない資産は次の3つです。

1. **事業承継・中小企業経営という縦のドメイン**（汎用AIアシスタントは持っていない）
2. **認定パートナーのネットワーク**（個人のAIツールには構造的に存在しない）
3. **顧客の時系列データ**（試算表・資金繰り・課題PDCA・面談履歴が一箇所にある）

この資産の上でしか成立しない機能が「唯一無二」になります。優先度順に：

### ① 朝刊ブリーフ「今日の一手」（Phase 1の中核）

毎朝、AIが担当顧客全社を読み終えた状態で「今日はこの3件。理由と、最初の一言はこれ」を提示。
**パートナーの1日が「何をすべきか考える」からではなく「AIの提案を確認する」から始まる。**
これが「最高のパートナー」体験の土台です。

### ② 面談前ブリーフ（最も感動が生まれる機能）

面談の前日に、その顧客の試算表推移・前回面談メモ・未完了課題・話すべきテーマ・想定質問への
回答案を1枚に自動生成。準備30分がゼロになり、新人パートナーでもベテランの面談品質が出せます。

### ③ 新人パートナーの「AI先輩」（参入障壁を下げる核心）

ご相談の「認定パートナーがもっとジョインしやすく」に直結する機能です。
研修プログラム・顧客状況・営業ツールを知っているAIが、新人に **次の一手を先回りで指示** します。
「初回面談が3日後ですね。この顧客の業種なら、この台本と、このシミュレーターを使いましょう」
——つまり **「経験」をプラットフォームが供給する**。未経験者でも初月から動ける状態を作れるのは、
ドメイン特化データを持つTsuguAiだけです。

### ④ 承継シグナル・レーダー

経営者年齢・後継者有無・財務状況・succession_checksから「承継の窓が開いた顧客」をAIが検知して
パートナーに通知。「そろそろ株価対策を始める時期です」を人間より早く言えるプラットフォームは
存在しません。

### ⑤ M&Aクロスマッチング（ネットワーク効果）

パートナーAの売り案件とパートナーBの買い候補を、AIが夜間に全件突合して双方に通知。
**パートナーが増えるほど全パートナーのAIが賢くなる** ——これは個人向けAIツールが
構造的に真似できない、ネットワーク効果そのものです。

### ⑥ 月次レポートの先回りドラフト

月初にAIが全顧客分のレポート草案を生成済みにしておく。パートナーは編集と承認だけ。
「AIが下書き、人が仕上げ、顧客に届く」——TsuguAiの「AIと人」の思想がそのまま形になります。

## 5. 信頼のためのガードレール（プロアクティブAIの成否を分ける点）

- **頻度の上限**: 働きかけは1日1回のブリーフに集約。個別アラートは本当に緊急のものだけ。
  うるさいAIは即ミュートされ、二度と開かれません
- **必ず「理由」を添える**: 「◯◯社をフォローすべき」ではなく「試算表が2ヶ月止まっているため」。
  根拠のない提案は信頼を毀損します
- **AIは提案まで、実行は人間**: メールは下書きまで、レポートは草案まで、送信・承認は必ず人。
  士業・承継の世界では、この一線が信頼の生命線です
- **RLS徹底**: agent_insightsは本人しか読めない。生成はservice roleのみ（同梱SQLで設定済み）
- **フィードバックループ**: 各提案に「役に立った/不要」ボタンを付け、ブリーフ生成プロンプトに
  過去の評価を反映（不要と言われた種類の提案を減らす）

## 6. コスト概算

| 項目 | 目安 |
|---|---|
| agent-heartbeat（パートナー50名・毎朝1回・claude-sonnet-4-6） | 月 $3〜10 程度 |
| pg_cron / Edge Functions | Supabase既存プラン内 |
| Resend（メール） | 月3,000通まで無料 |
| LINE公式アカウント | 無料枠あり（月200通〜、有効配信数で課金） |
| Google API | 無料（審査の工数のみ） |

Phase 1〜2は実質、追加コストほぼゼロで運用できます。

## 7. 次のアクション

1. 同梱のSQL（`supabase/migrations/`）をSupabaseのSQL Editorで実行
2. `supabase functions deploy agent-heartbeat` でデプロイし、`ANTHROPIC_API_KEY`（既存）と
   `CRON_SECRET`（新規）をSecretsに設定
3. SQL内のpg_cron設定のURL・シークレットを自環境の値に書き換えて有効化
4. index.htmlに「AIからの提案」表示を実装（通知センター最上部 + AI秘書冒頭）
5. 2〜3名のパートナーで2週間試験運用 → フィードバックでブリーフの精度を調整 → 全体公開
