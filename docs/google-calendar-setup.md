# Googleカレンダー連携（双方向）の立ち上げ手順

TsuguAi 側の作りは全部そろっています。あとは **Google 側でTsuguAiを名乗る許可をもらう**だけです。
ここだけは運営（株式会社福來）でないとできません。所要は、審査を除いて **30分ほど**です。

> **先に知っておいていただきたいこと**
> Google に「カレンダーを読み書きする許可」を求めるのは**慎重な扱いの権限**にあたり、
> 社外の方（顧客・パートナー）に使っていただくには **Google の審査**が要ります。
> 審査には**数週間**かかることがあります。
> ただし**審査の前でも、テストとして登録した100名までは今日から使えます**。
> 立ち上げの順番は、まずテストで運営が使い、並行して審査を出す、が現実的です。

---

## ① Google Cloud でプロジェクトを作る

1. <https://console.cloud.google.com/> を開く（会社の Google アカウントで）
2. 上部のプロジェクト選択 → **新しいプロジェクト**
3. 名前は `TsuguAi` など。作成

## ② カレンダーの API を使えるようにする

1. 左メニュー **API とサービス → ライブラリ**
2. `Google Calendar API` を検索して開き、**有効にする**

## ③ 同意画面（ユーザーに出る画面）を作る

1. **API とサービス → OAuth 同意画面**
2. User Type は **外部**（顧客・パートナーに使っていただくため）
3. 入力するもの

   | 欄 | 入れるもの |
   |---|---|
   | アプリ名 | `TsuguAi -継-` |
   | ユーザーサポートメール | 運営の連絡先 |
   | アプリのロゴ | TsuguAi のロゴ（審査のとき求められます） |
   | アプリのホームページ | LP の URL |
   | プライバシーポリシー | LP のプライバシーポリシーの URL |
   | 利用規約 | LP の利用規約の URL |
   | 承認済みドメイン | LP と Supabase のドメイン |
   | デベロッパーの連絡先 | 運営のメール |

4. **スコープ**で次の二つを追加

   ```
   https://www.googleapis.com/auth/calendar.events
   https://www.googleapis.com/auth/calendar.readonly
   ```

5. **テストユーザー**に、まず試す方のGoogleアドレスを入れる（100名まで）

> この時点で、テストユーザーに入れた方は**すぐ使えます**。
> 同意画面に「このアプリは Google で確認されていません」と出ますが、
> 「詳細」→「安全ではないページに移動」で進めます。社外の方に出すのは審査後にしてください。

## ④ クライアントID を作る

1. **API とサービス → 認証情報 → 認証情報を作成 → OAuth クライアント ID**
2. 種類は **ウェブ アプリケーション**
3. **承認済みのリダイレクト URI** に、次を**そのまま**入れる

   ```
   https://yaururnkxjhtiowkpvyu.supabase.co/functions/v1/google-oauth
   ```

4. できた **クライアント ID** と **クライアント シークレット** を控える

## ⑤ Supabase 側の設定

### SQL を流す

Supabase Dashboard → SQL Editor に、次の5つを**この順に**貼り付けて Run。

| 順 | ファイル | 確かめ |
|---|---|---|
| 1 | `supabase/migrations/20260916020000_google_calendar.sql` | つながりの表=1／予定の新しい列=4／関数=6／画面から鍵が読めるか=false |
| 2 | `supabase/migrations/20260917010000_pgcrypto_search_path.sql` | まだ直っていない関数=0／暗号化できるか=true |
| 3 | `supabase/migrations/20260917020000_google_relink_reset.sql` | 関数=1／札が残っている行=0 |
| 4 | `supabase/migrations/20260917030000_google_multi_account.sql` | つながりの主キー=id／送り先が二つある人=0／関数=8／暗号化できるか=true |
| 5 | `supabase/migrations/20260917040000_google_calendars.sql` | カレンダーの表=1／予定のカレンダー列=1／関数=3／札が残っている行=0 |

2 は「暗号の部品（pgcrypto）が `extensions` の棚にあって見えない」問題の手当てです。
これを飛ばすと、つなぐ手前で `pgp_sym_encrypt does not exist` と出て止まります。
4 は「1人で複数の Google アカウントをつなぐ」ための作り替えです。
5 は「アカウントの中のどのカレンダーを取り込むか」（家族・祝日・共有など）を選べるようにするものです。

### Secrets を入れる

Dashboard → **Edge Functions → Secrets** に5つ。

| 名前 | 中身 |
|---|---|
| `GOOGLE_CLIENT_ID` | ④のクライアント ID |
| `GOOGLE_CLIENT_SECRET` | ④のクライアント シークレット |
| `GOOGLE_REDIRECT_URI` | `https://yaururnkxjhtiowkpvyu.supabase.co/functions/v1/google-oauth` |
| `GOOGLE_STATE_SECRET` | 任意の長い文字列（32文字以上。誰にも見せない） |
| `APP_URL` | TsuguAi の画面の URL |

`GOOGLE_STATE_SECRET` は、同意の途中で「これは確かにこの人の依頼だ」と確かめる札の署名に使います。
これが短いと、他人のカレンダーを別の人に結び付けられてしまいます。**長く、推測できないもの**にしてください。

### Edge Function を2つデプロイする

Dashboard → Edge Functions → 新規作成で、それぞれ中身を貼り付けます。

| 名前 | ファイル | Verify JWT |
|---|---|---|
| `google-oauth` | `supabase/functions/google-oauth/index.ts` | **OFF** |
| `google-sync` | `supabase/functions/google-sync/index.ts` | **OFF** |

> **Verify JWT は必ず OFF** にしてください。
> Google が戻してくる URL には JWT が付かないため、ON のままだと弾かれます。
> 代わりに、関数の中で**自分でログインを確かめています**（`sb.auth.getUser`）。
> ログインしていない方が呼んでも、何も返しません。

## ⑥ 動くか確かめる

1. TsuguAi にログイン → 右下の継ナビくん → **「📅 予定」タブ**
2. いちばん下の **「Googleでつなぐ」** を押す
3. 同じ窓が Google の同意画面に変わる → アカウントを選んで **許可**
4. **自動で TsuguAi に戻り、予定タブが開いて、そのまま同期が走ります**
   （「つながりました」「同期しました（受け n件）」と出ます）
5. **Google に入れた予定がこの画面に出る**／**この画面で入れた予定が Google に出る**ことを確認

うまくいかないときは、予定タブの連携欄に理由が出ます。

> **Edge Function は画面を出しません。** Supabase の Edge Function は HTML を返しても
> 文字のまま表示されるため、結果は URL（`?gcal=ok` ／ `?gcal=err&m=理由`）に添えて
> TsuguAi に戻し、TsuguAi 側の画面で伝える作りにしています。`APP_URL` が空だと
> 戻れないので、必ず入れてください。

### つまずきやすいところ

| 出た言葉 | 意味 | 直しかた |
|---|---|---|
| `pgp_sym_encrypt does not exist` | 暗号の部品が別の棚にある | ⑤の SQL 2 を流す |
| `カレンダーが使えません` | その Google Workspace アカウントに**カレンダーの機能が付いていない**（Google からは `The user must be signed up for Google Calendar.` と返ります） | Google 管理コンソール → アプリ → Google Workspace → カレンダー を ON にする。難しければ個人アカウントでつなぐ。**つなぎ直しても直りません**。このアカウントには「送り先にする」が出ません（出せない先に送ると、予定が出ないまま溜まるため） |
| 同期は成功なのに予定が出ない | 古い札（syncToken）が残っている、または一意の索引が条件つき | ⑤の SQL 3・4 を流す（両方とも手当てが入っています） |
| Google に同じ予定が二つ出る | 以前の **ICS 購読（見るだけの連携）が残っている** | Google カレンダー左の「他のカレンダー」から TsuguAi の購読を削除する |

### 複数のアカウント（個人と会社など）

つないだあとに出る **「もう1つのアカウントをつなぐ」** から足せます。

- Google → TsuguAi は、つないだ**全部**から取り込む（アカウントごとに切れる）
- TsuguAi → Google は、**送り先に選んだ一つ**にだけ出す（両方に出すと二重になる）
- 送り先を変えても、すでに送った予定は動かさない（新しい予定から新しい送り先へ）
- 解除はアカウントごと。そのアカウントから取り込んだ予定だけが消える

### 他のカレンダー（家族・誕生日・共有・祝日など）

各アカウントの下に **「取り込むカレンダー」** の一覧が並びます（Google の画面左に出るものと同じ）。

- **メインだけ最初からオン**、ほかはオフ。祝日や誕生日を勝手に入れると週表示が読めなくなるため
- チェックを入れるとすぐ同期して入ります。外すと、そのカレンダーの予定だけ消えます
- 一覧は同期のたびに Google と合わせます。つないだ直後は空で、最初の同期のあとに並びます
- TsuguAi で入れた予定の送り先は**メインカレンダーのまま**（購読しているだけのカレンダーには書けません）
- 旧来の ICS 購読（「TsuguAi 継ナビくん」）は一覧に出しません。取り込むと TsuguAi の予定が戻ってきて際限なく増えるため

## ⑦ 審査を出す（社外の方に使っていただくため）

同意画面の設定ページから **「公開ステータス」→ 本番環境に移行 → 確認を申請**。

求められるもの：

- アプリのホームページ・プライバシーポリシー・利用規約（すべて同じドメイン）
- ロゴ
- **説明動画**（同意画面からカレンダーが同期されるまでを撮ったもの）
- **なぜその権限が要るかの説明**

説明に使える文面の案：

> TsuguAi は、中小企業の経営者と認定パートナーの面談予定・期日を扱う経営支援サービスです。
> 利用者ご本人のカレンダーと予定を双方向に同期し、二重入力をなくすために
> `calendar.events` を使用します。取得した予定は当該ご本人の画面にのみ表示し、
> 他の利用者・運営者には表示しません。第三者への提供・広告目的の利用は行いません。

## この連携でできること・できないこと

| | |
|---|---|
| どちらに入れても両方に出る | ○ |
| 反映の速さ | 画面を開いたとき（5分に一度まで）と「いま同期する」 |
| 取り込む範囲 | アカウントの中の**選んだカレンダー**（メインだけ最初からオン。家族・誕生日・共有・祝日などは本人がチェックを入れる） |
| 複数の Google アカウント | ○。取り込みは全部から、送り先は一つ |
| 継ナビくん・今日の一手 | 取り込んだ予定も「今日の予定」として読みます |
| 面談（TsuguAi → Google） | ○ |
| 面談（Google → TsuguAi） | **×**。顧客との約束なので、カレンダーの操作では消しません |
| 他の人から見えるか | **見えません**。予定はご本人だけが読めます（運営も読めません） |
| 更新用の鍵の置き場所 | 暗号化して保管。画面からは読めません |

## 私用の予定について

Google のメインカレンダーごと取り込むので、通院や家族の用事も TsuguAi に入ります。

- **他の人には見えません。** 予定の表（`agenda_events`）は本人だけが読める設定で、運営も読めません
- ただし、**継ナビくんに「今日の予定は？」と聞くと、その予定も材料として AI に渡ります**
- 見られたくない予定があるときは、予定タブのアカウントの欄で
  **「このアカウントの予定をこの画面に取り込む」のチェックを外して**ください。こちらから送るだけになります
- 「家族」だけ外す、のようにカレンダー単位でも外せます（**取り込むカレンダー**の一覧）

この点は、パートナー・経営者に**お伝えしたうえで**おつなぎいただくのが安全です。
